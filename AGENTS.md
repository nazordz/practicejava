## Project Overview

`practicejava` is a Spring Boot REST API for managing **users** and **books**.

| Aspect            | Choice                                                        |
|-------------------|--------------------------------------------------------------|
| Language          | Java 25                                                       |
| Framework         | Spring Boot 4.1.0 (Web MVC, Data JPA, Security, Actuator)     |
| Build             | Maven (`./mvnw`)                                              |
| Database          | PostgreSQL                                                    |
| Migrations        | Liquibase (formatted-SQL changelogs)                          |
| Cache             | Redis (`spring.cache.type=redis`)                             |
| Auth              | Spring Security with JPA-backed `UserDetails`, roles & permissions |
| Tests             | JUnit + Testcontainers (PostgreSQL)                          |
| Runtime           | Virtual threads enabled                                       |

### Layout

```
src/main/java/com/nazor/practicejava/
  config/   SecurityConfig, data seeders
  user/     User entity, Role, Permission, repositories, service, controller, dto/
  book/     Book entity, repository, service, controller, dto/
src/main/resources/
  application.yml
  db/changelog/   Liquibase master + formatted-SQL changesets
```

### Common commands

```bash
./mvnw clean compile        # compile
./mvnw test                 # run tests (spins up Testcontainers Postgres)
./mvnw spring-boot:run      # run locally
docker compose up           # Postgres + Redis via compose.yaml
```

The schema is **owned by Liquibase** — Hibernate runs with `ddl-auto: none`.
Never rely on Hibernate to create or alter tables; add a changeset under
`src/main/resources/db/changelog/` and register it in `db.changelog-master.yaml`.

## MCP servers

MCP servers are configured in [.mcp.json](.mcp.json).

| Server | Purpose |
|--------|---------|
| **postgres** | `postgres-mcp` (run via `uvx`) in `--access-mode=unrestricted`. Connects using `DATABASE_URI` (defaults to `postgresql://postgres:postgres@localhost:5432/postgres`). Use it to inspect schema, run/explain SQL, analyze indexes, and check DB health against the local Postgres. |

Because access mode is **unrestricted**, the postgres MCP can run mutating SQL.
Treat it as a real connection to the local dev database: prefer read-only
inspection (`list_objects`, `explain_query`, `get_object_details`) and only
mutate data when explicitly asked. Schema changes still belong in Liquibase
changesets, not ad-hoc MCP `execute_sql`.

## Model IDs: always use UUIDv7

Every persisted entity uses a **UUIDv7** primary key, generated by **PostgreSQL**
(not the application). UUIDv7 is time-ordered, which keeps B-tree index inserts
sequential and avoids the page-fragmentation/write-amplification you get with
random UUIDv4 keys — while still being globally unique and non-guessable.

The pattern is identical for the JPA entity and the migration:

**Entity (Java):**

```java
@Id
@Generated                       // value is produced by the DB, read back after insert
@ColumnDefault("uuidv7()")       // Postgres generates it via the column default
@Column(updatable = false, nullable = false)
private UUID id;
```

**Liquibase changeset (SQL):**

```sql
id UUID PRIMARY KEY DEFAULT uuidv7()
```

Rules for any new model:

1. Declare the id as `UUID`, never `Long`/auto-increment.
2. Annotate with `@Id @Generated @ColumnDefault("uuidv7()")` and mark the column
   `updatable = false, nullable = false`.
3. In the Liquibase changeset, define the column as `UUID PRIMARY KEY DEFAULT uuidv7()`.
4. Do **not** assign the id in application code or use `@GeneratedValue` strategies
   — the database owns id generation so ids are consistent whether a row is inserted
   via JPA, a seeder, or raw SQL.

> `uuidv7()` is a built-in Postgres function (PostgreSQL 18+). If targeting an older
> Postgres, provide an equivalent `uuidv7()` function or extension before migrating.
